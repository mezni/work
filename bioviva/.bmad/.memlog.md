# Memlog - BioViva Architecture Spine

## Initialization

- **Date**: 2026-11-05
- **Project**: BioViva
- **Altitude**: epic (system-wide architecture spine)
- **Purpose**: build-substrate (consistency contract for independently-built crates)
- **Paradigm**: hexagonal (DDD-style with ports/adapters, Axum as framework)

## Decisions Log

### AD-1: Design Paradigm — Hexagonal Architecture (DDD-style)
- **Type**: decision
- **Text**: Named paradigm is "hexagonal architecture" with DDD-style bounded contexts, Axum as the framework/router, and repository ports abstracting DB access. This carries a whole model for free: clear module boundaries, dependency injection of DB pool, route-level adaptation layers.
- **Binds**: All 7 bounded contexts (bio-auth, bio-core, bio-products, bio-producers, bio-orders, bio-users, bio-search)
- **Prevents**: Monolithic code mixing across contexts; arbitrary DB access from handlers; circular dependencies between crates
- **Status**: [ADOPTED]

### AD-2: Single DB Connection Pool
- **Type**: decision
- **Text**: Single `sqlx::Pool<Postgres>` in `bio-core` shared across all crates via DI. No per-crate pools. Enforced by code review; schema isolation not at DB level but at code level.
- **Binds**: All crates (bio-auth through bio-search)
- **Prevents**: N+1 connection issues; inconsistent pool sizes; per-crate migration drift
- **Status**: [ADOPTED]

### AD-3: Repository Pattern per Bounded Context
- **Type**: decision
- **Text**: Each crate implements its own `Repository` trait abstracting DB access. Traits are `Send + Sync + 'static`. Crates only access their own tables (enforced by code review, not DB isolation).
- **Binds**: ProductRepository in bio-products, ProducerRepository in bio-producers, OrderRepository in bio-orders, UserRepository in bio-users, CertificationRepository in bio-producers
- **Prevents**: Direct SQL in handlers; repository logic duplication across contexts; table access across context boundaries
- **Status**: [ADOPTED]

### AD-4: JWT Auth via Axum Extensions
- **Type**: decision
- **Text**: `auth_middleware` extracts/validates JWT, inserts `Claims` into Axum extensions. `permission_middleware` / `role_middleware` check before handler execution. No auth logic in handler bodies.
- **Binds**: bio-auth crate; all context routers via `Extension(AuthClaims)` injection
- **Prevents**: Duplicate auth checks in every handler; plaintext password handling; bypassed authorization
- **Status**: [ADOPTED]

### AD-5: Trust Score Calculation Invariants
- **Type**: decision
- **Text**: Trust Score (0-100) = 40% certification validity + 30% lab test results + 20% producer reputation + 10% review recency. Visible on all product cards. Recalculated on: certification update, new lab results, producer rating change, new review.
- **Binds**: bio-products (Product trust score), bio-producers (Producer reputation), bio-search (Recommendation filtering)
- **Prevents**: Arbitrary trust score manipulation; inconsistent calculation across contexts; missing invariant in recommendations
- **Status**: [ADOPTED]

### AD-6: Freshness Lifecycle States
- **Type**: decision
- **Text**: FreshnessState enum: Fresh (0-30 days since harvest), Ripe (31-60 days), Aging (61-90 days), Archived (>90 days). Products beyond 90 days removed from catalog. Handlers enforce: Order valid only for Fresh/Ripe; Subscription manages certification renewal; Search filters by min trust score + seasonal availability.
- **Binds**: bio-products (FreshnessCalculator), bio-orders (FreshnessEligibilityChecker), bio-search (TrustFilter)
- **Prevents**: Selling expired products; subscription past certification window; search showing stale products
- **Status**: [ADOPTED]

### AD-7: Role-Based Access Control
- **Type**: decision
- **Text**: Roles: guest | buyer | producer | admin. Permissions scoped per role. Middleware: `role_required("admin")`, `permission_required("orders:create")`. Checks from `Claims` in extensions before handler execution.
- **Binds**: bio-auth (role assignment), all contexts (role-based handler access)
- **Prevents**: Unauthorized role escalation; context-cross permission leaks; guest access to protected routes
- **Status**: [ADOPTED]

### AD-8: Docker Single-Container Deployment
- **Type**: decision
- **Text**: Multi-stage Docker: builder (rust:1.70) → runtime (ubuntu:22.04). Single container serves Axum app (API + static frontend). Env vars: DATABASE_URL, JWT_SECRET, JWT_EXPIRES_MIN, REFRESH_TOKEN_EXPIRES_DAYS, ARGON2_*, ACCOUNT_LOCKOUT_*, CORS_ORIGINS.
- **Binds**: Deployment infrastructure; CI/CD pipeline; production environment
- **Prevents**: Multi-container orchestration drift; dev/prod parity issues; manual env config gaps
- **Status**: [ADOPTED]

### AD-9: API Versioning at v1
- **Type**: decision
- **Text**: All API routes under `/api/v1/*` prefix. Auth at `/api/v1/auth/*`. Bounded contexts at `/api/v1/products`, `/api/v1/producers`, `/api/v1/orders`, `/api/v1/users`, `/api/v1/search`. Fallback handler serves React SPA at `/`.
- **Binds**: All API route definitions in bio-api router composition
- **Prevents**: Unversioned API breaks; route prefix inconsistency; SPA served at wrong path
- **Status**: [ADOPTED]
